# FrameMeld Fast：源帧率相对补帧策略

- 版本：`V0.1.4-fast.1`
- 构建类型：`fast`
- 策略 ID：`source-relative-fast-v1`

## 目的

Fast 版保留 FrameMeld 的命令行与 API，通过降低 `balanced`/`adaptive` 的中间
补帧时间轴来缩短导出耗时。Insight Agent 不需要修改；玩家只需把普通版的完整
FrameMeld 运行时目录替换为 Fast 版目录。

不要只替换 `ffmpeg.exe`。启动器、自动策略和 VapourSynth 帧引擎分别分布在
运行时根目录、`tools/` 与 `lib/`，混用不同版本可能导致能力信息与实际行为不一致。

## 自动策略表

| 输入帧率族 | Fast 中间时间轴 | 说明 |
| ---: | ---: | --- |
| `<56` | 最小整数倍达到至少 200 FPS | 保留低帧率质量下限 |
| 60 | 源帧率 ×4 | 60 FPS 实测样片为 240 FPS |
| 90 | 源帧率 ×3 | 270 FPS，相位感知输出到 60 FPS |
| 120 | 源帧率 ×2 | 240 FPS |
| 144 | 源帧率 ×2 | 288 FPS，相位感知输出到 60 FPS |
| 180 | 源帧率 ×2 | 360 FPS |
| 240 | 原生 | 跳过主 RIFE 补帧 |
| 其他 56–`<240` | 精确 240 FPS | 避免非标准源帧率被整数倍放大到过高 FPS |
| `>=240` | 原生 | 跳过主 RIFE 补帧 |

±0.5 FPS 容差只用于选择帧率族，实际目标始终由输入的精确有理帧率计算。例如
59.94 FPS 使用 `60000/1001 × 4`，不会先取整成 60。显式
`--interpolate-fps`、`--blur-amount`、`--performance-samples` 仍具有最高优先级。

## 已有对照数据

同一段 1920×1080、60 FPS、13.58 秒样片，在 RTX 5070 Ti、H.264 NVENC CQ20
条件下：原 300 FPS/5 抽头用时 72.766 秒；Fast 采用的 240 FPS/5 抽头用时
51.297 秒，单段提速约 1.42 倍、耗时减少约 29.5%。这是单一样片结果，不代表
所有分辨率、显卡或源帧率都能获得相同比例。
